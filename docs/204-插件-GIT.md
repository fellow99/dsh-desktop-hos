## 1. 目的

鸿蒙环境**没有 `git`**（toybox 不提供），`git` 全部命令不可用；本应用因此无法在设备上完成任何版本控制操作 —— 即使工作区里就有仓库。

本设计交付一个 dsh-desktop-hos 专用插件 `harmony-plugin-git`，把 **纯 JS 的 git 实现 isomorphic-git** 嵌入应用，向模型提供一组 git 工具，并提供**凭据设置页**管理带账号仓库的用户名/密码。全部操作发生在设备侧，不依赖任何外部二进制、不需要二进制证书、不触碰父工程。

**范围外（明确不做）**：`rebase`（isomorphic-git 无此原语，自研等于重写提交重放引擎）、`blame`、`grep`（已有 `grep` 工具）、SSH 传输（isomorphic-git 无 SSH 客户端，见 §3 F4）。

### 3.1 真机实测发现详录（第 1 轮）

三条发现都由真机实测暴露、并在同轮修复（提交 `e05b9f2` / `24a2e17` + `67abb70` / `759d5e6`）。

#### ① chroot 适配器被 isomorphic-git 判成 callback 方言 → 所有 git 调用永久挂起（已修，`e05b9f2`）

- **现象**：真机第一次 `git_init` 起，工具调用被记为 `ToolOutcomeUnknownError`（结果未知）；会话卡住，窗口显示「重新连接中」，主进程 inspector 拒连（主线程被卡死）。多次复现。
- **根因（文件/行级）**：isomorphic-git 的 `FileSystem` 用 `isPromiseFs()` 判 fs 方言 —— 它**无参调用 `fs.readFile()`** 并检查返回是否 promise-like；`plugins/harmony-plugin-git/lib/fs-adapter.js:57` 的 `resolveWithin(root, undefined)` 会**同步抛错**（`path.isAbsolute(undefined)`），探测因此被判成 callback 风格：11 个命令全被 `pify` 包成「等回调」，回调永不触发 → **永久挂起**（Node 事件循环仍健康，故不崩、不超时，只是不返回）。
- **修法**：`createRepositoryFs()`（`lib/fs-adapter.js:114`）的每个 `promises.*` 方法声明为 `async` —— async 函数不能同步抛错，探测即得 promise（这条硬契约就地写在 `lib/fs-adapter.js:117-128`）；并补 `rm`（`lib/fs-adapter.js:160`，`bindFs` 递归删除首选的命令）。
- **验证**：本机复现 —— 原生 `node:fs` 与 `{promises}` 桩都正常，只有该适配器每例挂到 8 s 超时；修复后 5/5 通过。真机隔离实验 `git.init via adapter ok ms=13`、`.git` 已创建。回归测试 `plugins/harmony-plugin-git/tests/fs-adapter.contract.test.mjs`（断言每个方法 `constructor.name === 'AsyncFunction'`、复刻 `isPromiseFs` 探测、逃逸/软链拒绝）。

#### ② 「Git 凭据」设置页状态恒为「状态未知」，且 describe 的失败被吞（已修，`24a2e17` + `67abb70`）

- **现象**：真机设置页两行都显示「状态未知」，而 `GIT_CREDENTIAL_<内网主机规整名>` 确实已在 `.credentials.yaml` 中；页面没有任何错误提示。
- **根因（文件/行级，两处）**：① 设置页 `save()`（`plugins/harmony-plugin-git/lib/client.js:234`）在 `await refresh()` **之后**写「已保存。」，把 describe 的报错覆盖掉（`lib/client.js:246-249` 的注释记录了这一点）；② 远端 `credentials.describe` 返回的是**信封 `{ok, value}`**，而页面按 ref 直接索引信封、而不是信封里的记录。
- **修法**：新增 `unwrapEnvelope()`（`lib/client.js:141`；`{ok,value}` 取 `value`、`{ok:false,error}` 抛出）与 `indexByRef()`（`lib/client.js:72`；容忍 object / Map / `[ref,info]` 数组 / 带 `ref|name|credentialRef` 的行，并折叠大小写与 `GIT_CREDENTIAL_` 前缀）；未匹配的 ref **如实保持「状态未知」**并显示 `describeShapeOf()`（`lib/client.js:114`）给出的形态诊断；**只有状态读取成功才说「已保存」**（`lib/client.js:249`）。
- **验证**：真机设置页重走「保存 → 状态回显」。① 的效果是错误不再被吞 —— 页面直接打印 describe 的返回形态，本轮据此看到 `读取凭据状态失败： (object keys: ok/value)`，这正是定位 ② 的依据；② 的效果是已配置的 ref 回显真实状态、未匹配的 ref 保持「状态未知」并附形态诊断、且只有状态读取成功时才出现「已保存。」。
- **附带记录（未修，留作后续）**：页面用 `localStorage` 记住「用户录入过的主机」（`lib/client.js:39/49`，与 §18 L6 是同一限制的另一半），而 webserver 端口每次启动都变 → origin 变化 → 重启后该列表为空，用户需要重新输入主机名（凭据本身在凭据库中，不受影响）。

#### ③ `git_diff` 静默丢弃 ref（已修，`759d5e6`）

- **现象**：`git_diff` 传 `ref:"HEAD~1"`（本部署的 git 库不支持祖先语法）**不报错**，落到默认 `mode:"head"`（HEAD↔工作区）并回「无变更」—— 把「不支持的写法」伪装成「没有差异」。
- **根因（文件/行级）**：`plugins/harmony-plugin-git/lib/tools/diff.js:199` 的 `const mode = args.mode ?? 'head'`（默认 `'head'`），而 `ref`/`ref2` 原先只在 `mode:"refs"` 分支（`lib/tools/diff.js:234-239`）被使用，其它模式直接忽略；两条参数描述当时也写着「ignored by the other modes」。
- **修法**：`mode !== 'refs'` 时传 `ref`/`ref2` **一律抛错**（`lib/tools/diff.js:203-210`）—— 错误文本说明该模式自身比较什么（`workdir` = index↔工作区、`staged` = HEAD↔index、`head` = HEAD↔工作区）并提示改用 `mode:"refs"`；两条参数描述（`lib/tools/diff.js:121`、`:128`）同步改为「其它模式传它是错误而不是被忽略」，并写明本部署不支持 `HEAD~1` 之类的祖先语法、要传分支/标签/`HEAD`/对象 id。
- **验证（已在设备上复跑）**：默认 `mode` + `ref:"HEAD~1"` 现在得到明确报错——设备原文：`Error: git_diff: ref is only meaningful with mode "refs" (which needs ref and ref2); mode "head" always compares HEAD with the working tree.`；同一仓库改用 `mode:"refs"` + 两个短 oid 仍产出真实差异（`变更文件数 1（modified README.md +1/-0）`）。修复前的对照行为是**不报错、回「无变更」**。原文见 §22.5-③。

## 4. 用户故事

- 作为用户，我希望在对话里直接让模型 clone 一个公开仓库并读懂它，不必先想办法装 git。
- 作为用户，我希望在设置里填一次带账号仓库的用户名/密码，之后模型执行 pull/push 不必知道密码。
- 作为用户，我希望模型**只在授权范围内**改动文件系统：工作区内自由操作，工作区外必须先经我审批。
- 作为用户，我希望任何失败都**如实说明原因**（缺凭据 / 认证失败 / 冲突 / 越界），而不是假装成功或静默重试。
- 作为用户，我希望知道哪些 git 操作**本平台做不到**（`rebase`），而不是让它悄悄用别的方式代替。

## 6. 方案对比

### 6.1 依赖供给 + 文件访问（主方案轴）

| | **A. 嵌套依赖物化 + 仓库根 chroot（采用）** | B. 扩展 `ctx.fs` seam 原语 | C. 插件内 vendored 单文件 bundle |
|---|---|---|---|
| 依赖 | `collect-dsh.mjs` 新增 `collectGitRuntime()`，形状照 `collectMarketPNPM()`（F7 先例）；闭包**嵌套在插件自己**的 `node_modules`（`.../harmony-plugin-git/node_modules/`）下；jsdiff 不物化、复用宿主闭包 | 同 A | rollup 预打成单文件 ESM 入库 |
| 文件访问 | 插件内 `node:fs/promises` 适配器，**以仓库根为 chroot** | git 全走 `ctx.fs`，需新增 5~6 个补丁 | 同 A |
| 上游改动 | 0 | 0（但补丁链变长） | 0 |
| 新增补丁 | **0** | **5~6**（`mkdir`/`rmdir`/`unlink`/`rename`/`readlink`/`symlink` + `fs-sandbox` 覆写） | 0 |
| 围栏 | 单点（仓库根）+ 复用既有提权审批 | 逐次经 `checkedTarget` | 同 A |
| 性能 | 好（chroot 内直连 node:fs） | 差（clone 上万次调用每次 `resolve` 含 realpath + 围栏判定） | 同 A |
| 适配层复杂度 | 小（POSIX 语义直给） | **大**（`FsTarget` 身份 + `FsWriteIntent` 版本守卫 + 每次传策略 ≠ 裸 POSIX） | 同 A |
| 构建期 | 需一次 npm 拉取（幂等缓存） | 同 A | **零联网** |
| 约定符合度 | 符合 | 符合 | **违反**「纯 ESM，无构建步骤」（生成物入库） |

**结论：采用 A。** B 被环境清单 §C.6 记录的补丁链上下文约束（每个补丁要 reverse-check + 往返 SHA 校验）与性能/适配成本双重否决；C 的「生成物入库」违反插件约定，且升级要手工重打。

**方案内被否决的子选项**：HTTP 客户端曾考虑 `isomorphic-git/http/web`（全局 `fetch`，依赖从 55 包降到 12 包 / 6.3 MB），最终采用 `isomorphic-git/http/node`（`simple-get`，走 node `http`/`https`）—— Node 路径是官方文档的推荐路径，POST/chunked 行为更可预期；体积差异不值得为此承担 `fetch` + 流式请求体（`duplex: 'half'`）的不确定性。

### 6.2 工具粒度

| | **A. 一动词一工具（采用，21 个）** | B. 单 `git` 工具 + `command` 枚举 |
|---|---|---|
| 与工程惯例 | 一致（`delete`/`move`/`copy`/`chmod`/`grep`/`glob` 都是「一工具一职责」） | 与 `str_replace_editor` 同形 |
| 模型可靠性 | 高（按名选工具 + 精确 schema，不必填联合类型参数） | 低（大联合 schema，易传错参） |
| 可独立验收 | 是（一个工具一组测试用例） | 否（全部耦合在一个入口） |
| 上下文成本 | 21 条 schema（较高） | 1 条长 schema（较低） |

**结论：采用 A。** 本需求的测试与验收要逐操作核对（§17），一动词一工具让「一个工具一组用例」的对应关系直接成立。

## 7. 架构与组件设计

### 7.1 挂载平面（本设计的核心论证）

环境清单给出两条互不可见的装配路径，本需求**两条都要**：

- 想要**工具**：需要在 agent 可见的注册表里出现；
- 想要**设置页 UI**：必须在 **host Loader** 里有行（F1），preset 行扫不到。

按 F3，host 平面的全局工具注册**对 agent 可见**（只有 scoped `tools.restrict()` 能屏蔽，而 `restrict()` 在全局上下文直接抛错，除 `subagent/child-agent.ts` 与 MCP 外无人调用，**preset 不做 restrict**）。因此**一行 host 行即可两全**：

```
┌─ desktop profile（profiles/desktop/cordis.patch.yml）────────────────┐
│  - insert:                                                          │
│    - id: git                                                        │
│      name: 'harmony-plugin-git'                                     │
│      # host 平面：① 注册 21 个 git 工具（全局可见 → agent 可用）    │
│      #            ② 声明 dsh.client → client-modules 扫到设置页     │
└─────────────────────────────────────────────────────────────────────┘
```

**为什么**不**沿用 `HARMONY_ENSURED_PRESET_ROWS`**（`plugins/README.md §二.7` 的常规做法）：把本插件挂到 preset 行会让它落在 **agent 平面**，其 `dsh.client` 声明**永远不会被扫描**（F1/F2），设置页交付物直接失效。反过来，host 单行同时满足两个交付物，且不与已有的三行 preset 工具插件产生任何重复注册。**这是对 §二.7 的有意例外**，需在 `plugins/README.md` 与本节同步登记。

**host 平面服务可就绪性已逐项核实**：`tools` / `fs-sandbox` / `sandbox-policy` / `credentials` / `authorization` 均在 base 或 web-app bundle 的 host 平面行中声明。

### 7.3 依赖物化

`collectGitRuntime()`，形状照抄 `collectMarketPNPM()`（现状 #7）：

- 常量 pin：`ISOMORPHIC_GIT_VERSION = '1.44.2'`（对齐 `DSH_MARKET_VERSION` / `PNPM_VERSION` 先例）；**没有** jsdiff 的 pin 常量 —— 插件侧 `lib/runtime.js` 只导出 `SUPPORTED_JSDIFF_MAJOR = 9`
- 在临时 staging 里 `pnpm add isomorphic-git@1.44.2 --config.node-linker=hoisted --ignore-scripts`（命令里**不含** `diff`）
- isomorphic-git 及其**整棵闭包**复制到 `dsh-dist/node_modules/harmony-plugin-git/node_modules/`（**插件自己的** node_modules）；jsdiff **完全不物化**
- **嵌套在插件自己目录下是关键**：`ensureDshPluginsProfileLink()` 每次启动把 `dsh-dist/node_modules/harmony-plugin-*` **整目录递归复制**（`cpSync`）到 `$DSH_HOME/profiles/node_modules/`，嵌套闭包随之过去，插件自身的裸 `import 'isomorphic-git'` 因此命中自己的嵌套层；若把闭包落在 dsh 顶层那一层（`dsh-dist/node_modules` 下，插件目录之外），那次复制反而带不上它 —— 复制源只取 `harmony-plugin-*` 目录。隔离效果不变：与 dsh 顶层同名包（`pako` / `ignore` / `buffer` / `readable-stream` / `simple-get` 等）绝不覆盖或冲突
- jsdiff 走宿主闭包：`plugins/harmony-plugin-git/package.json` 把它写进 `peerDependencies`（`"diff": "^9.0.0"`）；dsh 自身四个包（`dsh-tool-fs` / `dsh-workspace-changes` / `dsh-client-ui-trajectory` / `dsh-client-ui-primitives`）正式声明 `diff ^9.0.0`，`app-boot` 的 profile resolution 把 profile 内插件的裸包名请求路由进宿主闭包，设备实测解析结果即 `dsh-dist/node_modules/diff@9.0.0`。因此既不存在「本插件的 diff 覆盖 dsh 自身 diff」这一冲突面，也没有那 0.8 MB 增量
- 断言：入口存在且非空、版本号与 pin 一致；`lib/runtime.js` 对 jsdiff 只断言 major（`SUPPORTED_JSDIFF_MAJOR = 9`）与入口函数 `createTwoFilesPatch` 存在，版本清单读不出来时**警告而不失败**（`console.warn`），读到且 major 不符才抛错
- 幂等与失败方式：目标已有 `package.json` 即走快路径（快路径同样跑断言），但**正常构建每次先删 `distDir`，快路径在常规链路不可达**，只能靠单独二次调用 `collectGitRuntime()` 验证；`collectGitRuntime()` 与 `assertGitRuntimeArtifact()` **抛错**而不用 `process.exit(1)`（否则会跳过 `finally` 里的 staging 清理），终止进程由调用点 `try/catch` 统一负责
- 体积实测 55 包 / 8.6 MB（F8）。可选裁剪 `index.cjs` + `index.umd.min.js` + map → 约 5 MB，**默认不做**（裁剪第三方包内容属额外维护面）

## 8. 仓库根围栏（安全属性）

围栏决策点是**仓库根**，这是安全属性，不是待修的 bug：

1. 每个工具调用先 `ctx.fs.resolve(dir, { cwd: sessionCwd, signal })` → `ctx.fs.processPath(target)` 得到进程可见的**仓库根绝对路径**；这是后续全部路径的唯一来源。
2. 适配器内**每个路径** = `join(root, rel)` → `normalize` → **前缀包含校验**；越界（`..` 逃逸、绝对路径、软链指向根外）即拒，不落到 `node:fs`。
3. 仓库根落在会话工作区**之外**时不静默：抛 `FsError('FS_SANDBOX_DENIED')` + 复用 `@deepseek-ai/dsh-sandbox` 的 `sandboxDenialMarker` / `escalationHintMarker` / `ESCALATION_TARGETS` / `approveEscalation`，与 `harmony-plugin-fs-mutate/lib/sandbox.js` **完全同形** —— 写类工具暴露 `sandbox_permissions` + `justification` 两个参数，模型据此申请**一次性**提权，经用户审批后该次操作在批准的 `workspaceRoot` 下执行。
4. 用户目录（Desktop/Documents/Download）本就在 `DSH_EXTRA_WRITABLE_ROOTS` 内，批准后即可用；OS 授权是否已给由系统决定 —— **失败如实报错**，不重试、不换路径假装成功。

**已知取舍（如实声明）**：git 仓库**内部**的写入不逐次经过 `fs-sandbox.checkedTarget`，围栏收窄为「仓库根」单点。这与 `harmony-plugin-exec`（spawn shell 绕过 fs 围栏，环境清单 §C.5 条 2）同级，**且比它更严**（exec 完全无围栏）。

## 9. 凭据流程

### 9.1 命名规则（固定、可手工填写）

由于客户端可达的凭据 API 只认 `credentialRef`（现状 #9），git 凭据用**凭据 ref** 存放：

- key 名：`GIT_CREDENTIAL_<HOST>`，`<HOST>` = 目标 URL 的 `host[:port]` **大写化、非字母数字 → `_`**
  - `https://git.example.com/team/project.git` → `GIT_CREDENTIAL_GIT_EXAMPLE_COM`
  - `https://git.example.com:8443/team/project.git` → `GIT_CREDENTIAL_GIT_EXAMPLE_COM_8443`
- 值格式：`username:password`，按**第一个** `:` 切分（用户名中不含 `:`）

因此用户**既可以**在设置页填写，**也可以**直接编辑 `$DSH_HOME/.credentials.yaml` —— 两条路径落到同一处，命名规则在设置页就地展示。

### 9.2 运行期流程

```
git 操作需要认证（服务端返回 401/404 且未带凭据）
         │
         ▼
auth.js：从目标 URL 取 host → 规整为 key 名 → ctx.credentials.resolve(ref)
         （凭据库未命中则回落到 $DSH_HOME/.git-credentials，见 §9.4）
         │
     命中 ──► onAuth 返回 { username, password }  明文仅在 host 进程内存中流转
         │
     未命中 ──► onAuth 返回 { cancel: true }
                → 工具报错：「该主机未配置凭据，请在设置 → Git 凭据 中添加，
                  或写入 $DSH_HOME/.credentials.yaml 的 <key 名>，或在
                  $DSH_HOME/.git-credentials 加一行
                  <协议>://<username>:<password>@<host>」（见 §9.4）
                （不把裸 401 抛给模型；不猜测、不匿名重试）
         │
onAuthFailure ──► 认证被拒：报「凭据被拒绝」并指明 key 名，
                  最多重试 1 次，绝不无限重试
```

- 明文**进不了**对话、日志、`cordis.yml`：工具参数里没有凭据字段，插件只经 `ctx.credentials` 与配置目录下的 `.git-credentials` 读取（§9.4）。
- 凭据来源有两处、优先级与镜像规则见 §9.4：设置页保存过的主机以凭据库为准，其余情况以 `$DSH_HOME/.git-credentials` 为准；工具实际用到的凭据都会镜像回该文件。
- 无账号仓库（如公开的 github 地址）从不触发 `onAuth`，零凭据可完成 clone/fetch/pull/本地全部操作。

### 9.3 身份（`user.name` / `user.email`）

不是密钥，**不进凭据库**：由 `git_config` 工具写仓库本地配置；`Config` 默认值为 `{ name: 'yourname', email: 'yourname@somehost' }`（**刻意使用明显的占位值，不使用任何真实个人信息**）。真机测试首步用 `git_config` 显式设置可辨识身份（§17.1 AN-20）。

### 9.4 Git 原生凭据文件（`<dsh 配置目录>/.git-credentials`，`5c697bc`）

参考 git 自己的凭据存储机制（git-scm.com「Git Tools → Credential Storage」的 `git credential-store`），凭据在 dsh 凭据库之外**同时**落到 dsh 配置目录下的 `.git-credentials`：路径 = `$DSH_HOME/.git-credentials`，`DSH_HOME` 未设时退回 `~/.dsh/.git-credentials`（与 `.credentials.yaml`、`profiles/` 同目录；实现为 `plugins/harmony-plugin-git/lib/git-credentials.js` 的 `dshConfigDir()` / `gitCredentialsPath()`）。

- **格式＝git 原生**：一行一条凭据，每行是一个**带 userinfo 的 URL** —— `<协议>://<username>:<password>@<host>`，与 `git credential-store` 同形；userinfo 两个字段都做百分号编码，因此口令里的 `:`、`@`、`/` 可原样往返。文件可手工编辑、可随 `$DSH_HOME` 整份拷走。
- **解析容忍**：空行、`#` 注释、非 URL 行、无 userinfo 行一律跳过而不抛错 —— 手工编辑的文件不该让所有 git 操作失败。
- **匹配（对齐 `git credential-store`）**：协议与 host（含端口，大小写不敏感）必须一致；**带路径的行按前缀匹配且优先于裸主机行**；同分则**文件里靠后的行覆盖靠前的**（git 记录的覆盖规则）。
- **写入**：临时文件 + `rename` 原子替换，保留其余所有行与注释；强制权限 `0600`（已是宽松权限的文件也被这次替换收回）。同一 `协议 + host + 用户名` 视为同一条（替换而非追加）；同 host 的不同用户名是第二条凭据（与 git 一致）。**删除**：只删匹配行，若删空则删掉文件本身。
- **来源优先级（本次改造的要点）**：
  - 设置页写入的 dsh 凭据库**优先** —— 对「用户在设置页保存过的主机」以凭据库为准（那是最新意图）；
  - 其余情况（例如从工作站拷来的、或手工编辑的 `.git-credentials`）**以该文件为准**；
  - 无论走哪个来源，**只要 git 工具真正用到了凭据，就把该条镜像写回 `.git-credentials`**（`auth.js:mirrorToFile`；尽力而为 —— 配置目录只读 / 写满**不得**让已有凭据的操作失败）；
  - 因此该文件既可用、又保持真实：`$DSH_HOME` 整份拷走时，别处的 `git` 二进制也能直接使用同一份凭据（这正是本次改造的目的）。
- **失败文案**：缺凭据的报错点名凭据库的键名 `GIT_CREDENTIAL_<HOST>`、设置入口与文件路径，并给出可直接照抄的占位行 `<协议>://<username>:<password>@<host>`；凭据被拒的报错点名键名与该文件路径（`auth.js:missingMessage` / `rejectedMessage`）。
- **设置页文案**：引导行改为「需要认证的远端所用的凭据；保存在 ~/.dsh/.git-credentials（git 原生格式，可手工编辑）。」（英文对应句同步，`lib/client.js`）。
- **边界（照实）**：
  - 页面**不是**该文件的直接编辑器：页面的保存仍写凭据库，文件由宿主半边按上面的规则读取与镜像 —— 因此「保存后文件立即出现该行」并不成立；该行在**该主机的凭据被实际使用后**出现 / 更新（§12 交互期流程图已同步登记）。
  - 设置页「已录入主机」的列表仍存在页面本地（`localStorage`），webserver 端口每次启动变化导致重启后该列表为空 —— 这一条**未改**（凭据本身在凭据库与文件里，不受影响；§18 L6 / §22.4-1）。
  - 明文因此出现在两处：dsh 凭据库与 `<dsh 配置目录>/.git-credentials`（`0600`）；仍不进对话、日志、`cordis.yml`（AC-8；R10 已同步）。
- **测试**：`plugins/harmony-plugin-git/tests/git-credentials.test.mjs` 9 例全部通过（§20 验证策略、§22.6、AC-13）。

## 11. 三个自建能力（isomorphic-git 缺口）

### 11.1 `show`

读 `readCommit` / `readTree` / `readBlob` / `readTag` 拼装输出：提交元信息（作者、时间、parents、message）+ 变更清单 + 逐 blob 内容。无需新依赖。

### 11.2 `diff`

`statusMatrix` 给变动清单，`readBlob` 取两侧字节，**宿主闭包** jsdiff（`diff ^9.0.0`）的 `createTwoFilesPatch` 产出标准 unified diff。

- `stat` 模式：只汇总新增/删除/修改行数。
- `pathspec` 过滤：只对匹配路径取 blob。
- **二进制检测**：含 NUL 字节即判二进制，输出 `Binary files a/… and b/… differ`，**不做文本 diff**（避免把二进制当文本吐给模型）。

### 11.3 `revert`（自建，fail-closed）

`cherryPick` **没有** `reversal`（F5），故按如下算法实现：

1. `readCommit({ oid })` 取目标提交；**恰好 1 个父提交**才继续，否则明确拒绝（不做合并提交的反向）。
2. 枚举父提交与目标提交之间的**变更路径**（两棵 tree 对比）。
3. 对每个变更路径：把**父提交**的内容物化到工作区（父无此路径 → 删除该路径）。
4. `add` 上述路径 → `commit`（消息模板 `Revert "<原提交标题>"`）。

**冲突语义（fail-closed）**：第 3 步前先比对工作区该路径的 blob oid 与目标提交是否一致。不一致说明工作区已分叉 —— **拒绝执行并明确报出冲突路径**，绝不静默覆盖用户改动。

```
启动期（构建期产物已就位）
  collect-dsh.mjs         collectGitRuntime() → dsh-dist/node_modules/harmony-plugin-git/node_modules/
                                                （isomorphic-git + 整棵闭包；jsdiff 复用宿主闭包，不物化）
  collect-dsh 阶段 8       profiles/desktop → dsh-dist/profiles/desktop
  首次启动解压 dsh-dist     → $DSH_HOME/dsh-dist

  runProfile('desktop')    叠加 profile patch：
                             └ insert 行 git = harmony-plugin-git（host 平面）
  host Loader 装载该行 → apply() 注册 21 个工具（全局可见，F3）
  client-modules 扫描 host Loader entries → 发现 dsh.client
                       → /plugins/git/client.js 纳入 __DSH_BOOT__ 启动图（F1）

交互期（模型调用）
  工具调用(dir, …)
    ├ fence.js: ctx.fs.resolve → processPath → 仓库根
    │            └ 越出工作区 → FsError(FS_SANDBOX_DENIED) + 提权提示
    │                           └ 模型带 sandbox_permissions+justification 重试
    │                              → approveEscalation → 用户审批 → 继续
    ├ runtime.js: isomorphic-git 动态装载（版本断言）
    ├ fs-adapter.js: 全部文件 IO 在仓库根内（chroot 校验）
    ├ auth.js: 需要认证时 → 凭据库（设置页保存过的主机优先，回落 $DSH_HOME/.git-credentials）→ onAuth，并把用到的凭据镜像回该文件（§9.4）
    └ report.js: 结构化结果 → 模型可读文本

交互期（设置页）
  settings.section「Git 凭据」(client.js)
    ├ 输入 host / 用户名 / 密码 → ctx.remote.credentials.set(ref, "user:pass")
    ├ describe(refs) 回显 configured / source / writable（永不返回值）
    ├ unset(ref) 删除

    └ host 列表由 localStorage 记忆（凭据 API 无法枚举 ref，见 L6）
```

## 13. 错误处理

| 场景 | 表现 |
|---|---|
| 目标目录不是仓库 | 明确报「不是 git 仓库」并给出 `git_init` / `git_clone` 建议，不静默创建 |
| 缺凭据（服务端要认证） | §9.2 / §9.4：指出该 host 对应的 key 名、设置入口与 `<dsh 配置目录>/.git-credentials` 路径，并给出可照抄的占位行 |
| 凭据被拒 | 报「凭据被拒绝」+ key 名与 `.git-credentials` 路径，最多重试 1 次 |
| 合并 / 摘取冲突 | `abortOnConflict` 保持默认 `true`（不污染工作区），报冲突路径，提示可 `git_merge` 中止 |
| `revert` 工作区已分叉 | §11.3 fail-closed 拒绝并列出冲突路径 |
| 越出工作区 | `FS_SANDBOX_DENIED` + 提权提示；审批拒绝时如实报「用户拒绝提权」 |
| 用户目录 OS 未授权 | `EPERM`/`EACCES` 原样归因（环境清单 A.2 #6），提示需系统设置授权并重启 |
| 网络不可达 / DNS 失败 | 报出主机名与底层错误，不假装成功 |
| 远端拒绝推送（non-fast-forward） | 原样报服务端 `PushResult.error`，**不自动 force** |
| clone 体积 / 超时 | 报出已用时与建议（`depth` / `singleBranch`）；取消经 `signal` 透传 |
| 调用被取消 | 停止执行并交由注册表处理取消语义，不当作失败报告 |

## 18. 约束与已知限制

- **L1 `rebase` 不支持**：isomorphic-git 无此原语（F5）。工具会明确报「本平台不支持」，不静默用 merge 冒充。
- **L2 SSH 不可用**：只能 HTTPS 用户名/密码；`git@host:path` 与 `ssh://` 地址被 isomorphic-git 改写为 `https://`（丢弃用户名），因此需配套的账号密码凭据。
- **L3 依赖体积**：`dsh-dist` 增加约 8.6 MB（**只有** isomorphic-git 闭包 55 包 / 8.6 MB；jsdiff 复用宿主闭包，零增量）。
- **L4 纯 JS 性能**：clone 大仓库明显慢于原生 git；本设计提供 `depth` / `singleBranch` / `noTags` 作为缓解，但不改变量级。
- **L5 围栏粒度**：git 仓内部写入不经逐次 `fs-sandbox.checkedTarget`（§8 已声明）。
- **L6 凭据页无法枚举**：凭据 API 不暴露 ref 枚举（现状 #9），设置页的 host 清单由 `localStorage` 记忆；直接编辑 `.credentials.yaml` 添加的 host 不会自动出现在页面上（页面会提示该限制）。
- **L7 无提示交互**：本需求不交付「运行时弹窗索要凭据」的交互（客户端无 authorization 流程面，现状 #9）；缺凭据时只给指引。
- **L8 哈希算法**：仅 SHA-1 仓库（isomorphic-git 现状）；SHA-256 仓库不在范围。
- **L9 二进制差异**：二进制文件只报 differ，不出内容级 diff（§11.2）。
