## 1. 目的

dsh-desktop-hos 的 ACL 已能访问三个用户目录：桌面、文档、下载；主进程也已把它们写入 dsh 可写白名单（`DSH_EXTRA_WRITABLE_ROOTS`）。

但「添加工作区」弹出的「选择工作区目录」对话框只能浏览沙箱内目录，无法把用户目录中的文件夹注册为工作区，已授权的用户目录能力无法从该入口被使用。

本设计交付一个 dsh-desktop-hos 专用插件 `harmony-plugin-workspace-picker`，替换现有对话框：顶部可切换四个主目录（沙箱 / 桌面 / 文档 / 下载），切换后在对应目录内完成列目录、新建文件夹、选择等操作。

对话框只能看到沙箱的根因：不是后端能力缺失，而是 **HOME 被重定向到沙箱后，浏览起点与默认视野落在沙箱内**。

## 3. 关键事实

| # | 事实 | 含义 |
|---|---|---|
| F1 | 两个 directoryFlow slot 是 single/root 作用域，owner 契约为 `{ open, busy, onPicked(path), onCancel, onError(message) }` | 替换点天然存在，填同两个洞即可，无需改 dsh 前端 |
| F2 | dsh 支持 dual-face 单包：host 面（Node）+ client 面（package.json 声明 `dsh.client`，经 `ctx.slots.register` 注入 React），dsh-market 是现成范例 | 一个包可同时承载后端装配与自定义对话框 UI |
| F3 | browse 后端支持全文件系统范围，`list` 返回 `{ path, home, crumbs, entries, truncated }`，entries 默认上限 1000 | 用户目录浏览复用同一原语，无需自实现 FS |
| F4 | 三个用户目录路径可从 `process.env.DSH_EXTRA_WRITABLE_ROOTS` 解析，delimiter 分隔、顺序固定 Desktop/Documents/Download | 插件运行期 HOME 已指向沙箱，必须从该环境变量解析，不能再用 `os.homedir()` |
| F5 | ArkTS 侧 `ContextPathAdapter.getUser*Dir` 存在但**全部返回空串**，且未在 `ContextPathAdapterBind` 绑定到 JS | 不依赖该适配器；路径走 F4 |
| F6 | JS 侧可经主进程 JSBind 调用 `PermissionManagerAdapter.CheckPermissions` / `RequestPermissionCode`（type 为 `directory_desktop` / `directory_document` / `directory_download`），回调分别返回 boolean 与授权码（0 = 已授权） | 未授权时可在对话框内主动弹系统授权窗 |
| F7 | `web_engine/src/main/module.json5` 已声明 `READ_WRITE_DESKTOP/DOCUMENTS/DOWNLOAD_DIRECTORY` 与 `FILE_ACCESS_PERSIST`；桌面目录为 system_basic（需 ACL），文档/下载为 normal（首次访问弹窗） | OS 层授权前提已具备 |
| F8 | auto 行用内存生成的 ID 动态挂载客户端面，无法用静态 `disabled: true` 精确定位其客户端面 | 组合层替换需禁用整个 auto 行，再静态直挂 browse 后端行 |

## 4. 用户故事

- 作为用户，我希望在「选择工作区目录」对话框中切换到桌面/文档/下载，以便把这些已授权目录中的文件夹注册为工作区。
- 作为用户，我希望选定主目录后能自由进入子文件夹、新建文件夹并选中，以便精确指定工作区位置。
- 作为用户，当某个用户目录尚未授权时，我希望在对话框内直接完成授权并继续，不必跳到系统设置再返回。
- 作为用户，我希望下次打开对话框时默认停留在上次使用的主目录，减少重复切换。

## 5. 功能需求

### FR-1 主目录切换

- FR-1.1 对话框顶部渲染四个主目录 Tab：**沙箱 / 桌面 / 文档 / 下载**。
- FR-1.2 切换主目录时：重置浏览栈为该主目录根，清空选中列，重新列目录。
- FR-1.3 默认主目录取上次使用值（见 FR-7）；首次使用默认为「沙箱」。

### FR-2 主目录解析

- FR-2.1 沙箱主目录 = `join(app.getPath('userData'), 'workspace')`（真机形态 `/data/storage/el2/base/files/workspace`）；每次打开对话框时检查，**不存在则自动创建**（`mkdir { recursive: true }`）。
- FR-2.2 桌面 / 文档 / 下载主目录从 `DSH_EXTRA_WRITABLE_ROOTS` 按顺序解析：Desktop、Documents、Download。
- FR-2.3 解析失败（环境变量缺失或条目为空）时：对应 Tab 仍可见，但内容区显示明确的不可用说明与重试入口；不得回退到其他主目录。

### FR-3 目录浏览（Miller 列）

- FR-3.1 沿用 680×500 Miller 列视图：未选中时单列全宽；选中文件夹后向右展开其子级新列。
- FR-3.2 只列目录，名称排序；仅展示非隐藏条目（**不提供「显示隐藏文件」开关**，直接不渲染宿主标记的 hidden 项）。
- FR-3.3 面包屑从文件系统根生成的 crumbs **截断为当前主目录根**：最高可点击到该主目录根，不显示根之上的层级。
- FR-3.4 移除手动路径输入（铅笔/路径编辑区）：UI 中不存在任意路径提交入口。
- FR-3.5 entries 超过 1000 时展示后端 `truncated` 提示文案。

### FR-4 新建文件夹

- FR-4.1 提供「新建文件夹」按钮，弹出嵌套 Modal，输入单个目录段名称（后端 zod 校验）。
- FR-4.2 默认名称 `未命名文件夹` / `Untitled folder`，同级冲突时追加序号（`未命名文件夹 2`、`3`…）。
- FR-4.3 创建成功后重新列目录并选中新文件夹。

### FR-5 选择与采纳

- FR-5.1 「打开」采纳当前选中文件夹；无选中时采纳当前列所在目录。
- FR-5.2 通过 owner 契约 `onPicked(绝对路径)` 回传，复用 ui-workspace 现有 `createWorkspace({ path })` 采纳链路，不改采纳语义。
- FR-5.3 「取消」或关闭对话框触发 `onCancel`。

### FR-6 授权处理

- FR-6.1 列目录返回 `EACCES`/`EPERM` 时，先经 `CheckPermissions` 预检；未授权则在**对话框内**调 `RequestPermissionCode` 主动弹出系统授权窗，按钮进入 loading 态。
- FR-6.2 授权成功（回调 0）后自动重试列目录；授权失败或拒绝时展示原因说明 + 「去系统设置」入口（`ContextPathAdapter.ShowSystemSettings`），返回后可手动重试。
- FR-6.3 授权流程不改变 owner busy 语义之外的全局状态；授权弹窗与对话框为同一交互事务。

### FR-7 主目录记忆

- FR-7.1 主目录选择持久化到浏览器 `localStorage`（键由插件私有命名空间拥有）。
- FR-7.2 **只记忆主目录，不记忆子路径**：再次打开对话框停留在该主目录根。
- FR-7.3 存储值非法（不属于四个主目录 id）时回退为「沙箱」。

## 6. 方案对比

| | A. Client-only + Slot shadow | B. 组合层替换 + dual-face（推荐） | C. 完全独立 dual-face |
|---|---|---|---|
| 后端 | 复用 auto 挂载的 browse | 禁 auto 行，静态直挂 browse 后端行，复用全部 list/createDirectory | 自实现列目录/建目录 |
| 前端 | 以 priority=-1 阴影覆盖两个洞 | 独占两个 directoryFlow 洞 | 独占两个洞 |
| 冲突 | 两个 occupant 共存，靠优先级压制 | 无冲突（官方 swap point 语义） | 需自行处理沙箱围栏 |
| 改动面 | 最小，但残留不渲染的上游客户端面 | profile patch + 一个插件包 | 最大，重复造轮子 |
| 上游升级 | browse surface 变化可能影响阴影 | 接缝稳定（auto 只是组合器） | 需长期跟随 dsh FS 语义 |

**结论：采用 B。** 该方案即 F8 推导出的「禁 auto + 直挂 browse 后端」：后端原语全部复用，客户端面由本插件独占，是 directory-picker seam 文档化的替换点。

## 7. 架构与组件设计

```
┌─ desktop profile（profiles/desktop/cordis.patch.yml）───────────────┐
│  - id: directory-picker          # web-app 的 auto 行                │
│    disabled: true                # 不再动态挂载 browse 后端+客户端面  │
│  - insert:                                                          │
│    - id: directory-picker-browse                                    │
│      name: '@deepseek-ai/dsh-host-directory-picker-browse'          │
│      # 仅 browse 后端：注册 directoryPicker seam（list/createDirectory）│
│    - id: workspace-picker                                           │
│      name: 'harmony-plugin-workspace-picker'                        │
│      # 本插件：空 host apply + dsh.client 客户端面                   │
└─────────────────────────────────────────────────────────────────────┘
                               │ RPC namespace: directoryPicker
┌─ harmony-plugin-workspace-picker（plugins/，dual-face）─────────────┐
│  Host 面 (lib/index.js)：命名导出 name/inject/apply；apply 为空，     │
│           仅使包进入 Loader roster（对齐 browse 包 node 半写法）。    │
│  Client 面 (lib/client.js)：                                        │
│    ├─ RootTabs           主目录切换 Tab（FR-1）                     │
│    ├─ RootResolver       root id → 绝对路径（FR-2，含沙箱自动建目录） │
│    ├─ MillerBrowser      Miller 列：列目录/下钻/截断面包屑（FR-3）   │
│    ├─ NewFolderModal     新建文件夹（FR-4）                         │
│    ├─ PermissionGate     EACCES/EPERM → 预检/主动申请/重试（FR-6）  │
│    └─ WorkspacePickerFlow  owner 契约适配，onPicked 回传（FR-5）    │
│  注册（沿用 browse 包 generator 事务写法，两个洞一个事务）：          │
│    conversation.hero.workspace.directoryFlow                       │
│    sidebar.workspaces.directoryFlow                                │
└─────────────────────────────────────────────────────────────────────┘
```

组件边界（单一目的、可独立理解与测试）：

| 单元 | 输入 | 职责 | 依赖 |
|---|---|---|---|
| `RootTabs` | 当前 root id | 渲染四个 Tab，切换时上抛切换事件 | 无 |
| `RootResolver` | root id | 解析绝对路径；沙箱根确保存在 | env / electron path |
| `MillerBrowser` | root 绝对路径 | 列目录、维护列栈、截断面包屑渲染 | `directoryPicker/list` |
| `NewFolderModal` | 当前选中路径 | 名称输入与默认名去重 → 建目录 → 选中 | `directoryPicker/createDirectory` |
| `PermissionGate` | 列目录错误 | 预检 + 主动申请 + 成功重试/失败引导 | JSBind 权限桥 |
| `WorkspacePickerFlow` | owner props | 串联上述组件，实现对话契约 | 全部 |

客户端面数据通道遵循 client 插槽纪律：组件不接触 ctx，所有数据与回调经注册的 `inject` 工厂从 apply 闭包取得（`listDirectory` / `createDirectory` 经 `ctx.uiWorkspace`，`t` 经 `ctx.locale.bind`），私有浏览态用组件局部状态，跨重开需保留的主目录 id 用 `localStorage`。

## 8. 根围栏（安全属性）

选定主目录后浏览域被锁定，这是**安全属性，不是待修的 bug**：

1. 浏览栈第一列锁定为该主目录根的 `list` 结果；下钻只接受当前列条目产生的子路径。
2. 面包屑点击目标最高为主目录根（FR-3.3），根之上 crumb 不渲染。
3. 无手动路径输入（FR-3.4），UI 层不存在提交任意绝对路径的入口。
4. `RootResolver` 返回值是全部后续操作唯一的路径来源；切换主目录必须经 `RootTabs` 重置整栈。

因此四个主目录互为隔离浏览域：可向下自由穿越，不能上溯，不能横向越界。

## 9. 数据流

```
启动期
  ensureSandboxHome()          HOME/USERPROFILE → userData（沙箱）
  installExtraWritableRoots()  DSH_EXTRA_WRITABLE_ROOTS = Desktop:Documents:Download
  runProfile('desktop')        叠加 profile patch：
                                 ├ directory-picker(auto)  disabled
                                 ├ directory-picker-browse 后端行（seam 能力）
                                 └ workspace-picker        本插件行（dsh.client）
  client-modules 扫描启用的 Loader 行 → 发现本插件 dsh.client
                               → /plugins/harmony-plugin-workspace-picker/client.js
                                 纳入 __DSH_BOOT__ 启动图

交互期
  点击「添加工作区」 → flowOwner.open = true
  WorkspacePickerFlow
    ├ 读 localStorage 主目录 id（默认 sandbox）
    ├ RootResolver：sandbox → ensure userData/workspace；其余 → 解析环境变量
    ├ directoryPicker/list(root) ────────────────► MillerBrowser 渲染
    │     │
    │     └ EACCES/EPERM → PermissionGate（见 §10）
    ├ 下钻：list(子路径) → 追加列；面包屑上跳（≤root）→ 截断列栈
    ├ 新建文件夹：createDirectory(path, name) → 重新 list → 选中新列
    └ 打开 → onPicked(绝对路径)
                → ui-workspace adoptDirectory → createWorkspace
                    ├ 成功：关闭流程，onPick(workspaceId)
                    └ 失败：错误 Modal（含「重试」）
```

## 10. 授权流程

```
list 返回 EACCES/EPERM
        │
        ▼
CheckPermissions(type) ── 已授权 ──► 视为瞬时错误，直接重试 list
        │
      未授权
        ▼
RequestPermissionCode(type)         # directory_desktop / directory_document / directory_download
        │                 （对话框进入 loading，取消其他操作）
        ├ 回调 0（已授权）────────► 重试 list，正常渲染
        ├ 回调非 0 / 拒绝 ────────► 展示原因 +「去系统设置」(ShowSystemSettings)
        │                            返回后用户手动「重试」
        └ 桥不可用/无 active context ► 明确归因提示 + 重试，不静默失败
```

type 与权限映射（`PermissionManagerAdapter.ets`）：`directory_download → READ_WRITE_DOWNLOAD_DIRECTORY`、`directory_document → READ_WRITE_DOCUMENTS_DIRECTORY`、`directory_desktop → READ_WRITE_DESKTOP_DIRECTORY`。

## 11. 错误处理

| 场景 | 表现 |
|---|---|
| 主目录不可读（非授权原因） | 内容区就地显示 `directory-picker/unreadable` 对应文案 + 重试，不关闭对话框 |
| 未授权 | 走 §10；不把原始 `EACCES` 直接抛给用户 |
| 新建目录同名 | 后端 `directory-picker/exists`：Modal 内提示名称冲突，留在输入态 |
| 新建目录失败 | `directory-picker/create-failed`：Modal 内提示，可改名重试 |
| 主目录路径无法解析（FR-2.3） | 该 Tab 内容区显示不可用说明 + 重试，不静默换根 |
| 采纳工作区失败 | 复用现有错误 Modal（含重试），与当前行为一致 |
| entries 超上限 | 展示 `truncated` 文案（FR-3.5） |
| 桥/active context 不可用 | 明确归因提示，不静默、不假装成功 |

浏览类失败在对话框自有区域内消化，不驱动 owner 的 `onError`；只有采纳阶段错误进入 owner 错误链路（对齐 browse 包语义）。

| 6 | 构建物化 | `scripts/collect-dsh.mjs` `collectPlugins()` | 已按 `harmony-plugin-*` 通配自动物化，**新包无需改收集脚本**（缺 package.json/命名不符硬失败） |
| 7 | 运行期镜像 | `src-main/main.js` `ensureDshPluginsProfileLink()` | 已自动镜像 `harmony-plugin-*` 到 `profiles/node_modules` 并清理同族陈旧目录 |
| 8 | 插件 README | `plugins/.../README.md` | 配置、根围栏语义、Known Limitations |

注意：本插件为 **root 作用域 UI**，与现有三个经 `HARMONY_ENSURED_PRESET_ROWS` 挂载的会话工具插件不同——**不**加入该 preset 行表，其根 Loader 行由 profile patch（落点 5）提供。browse 后端行所引用的包已在 web-app `package.json` 声明依赖（`@deepseek-ai/dsh-host-directory-picker-browse`，满足裸行解析前提）。

## 15. 约束与已知限制

- 本对话框只面向**四个已授权主目录**；不提供整盘浏览，不恢复手动路径输入（FR-3.4）。
- 用户目录的 OS 层授权前提是 F7 三项权限；桌面目录为 system_basic ACL，上架前须按 `docs/ACL申请清单-v2.md` A2-c 复核其进入发布 Profile。
- 不依赖 ArkTS `ContextPathAdapter.getUser*Dir`（当前为空实现，F5）；若未来改用系统 API 取路径，需补适配器、增加 JS 绑定并走 overlay 登记，属独立变更。
- entries 上限 1000 为 browse 后端既有行为，超限仅提示不分页。
- 仅支持选择目录，不支持文件选择、多选。

## 16. 风险与遗留

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 根 Loader 行 `harmony-plugin-workspace-picker` 的运行期裸名解析路径未在本次静态证实（现有直接证据为 dshmarket 根行 + `profiles/node_modules` 镜像） | 插件行可能解析失败 | 实施首步做启动 PoC：以 hilog「已复制 .../profiles/node_modules」与插件树激活状态确认；失败再补 profile 层解析配置 |
| R2 | 禁 auto 后若 browse 后端行配置不完整，directoryPicker seam 缺失 | 添加工作区入口消失（洞未被占） | profile patch 中 browse 后端行与本插件行同事务加入；AC-10 启动断言 |
| R3 | 桌面 ACL 在发布 Profile 中缺失 | 桌面 Tab 授权失败 | 上架前按 ACL-v2 复核；失败不影响文档/下载/沙箱 |
| R4 | 授权弹窗时序（无 active context） | 主动申请失败 | FR-6 / §11 已作明确归因与重试，不静默 |
| R5 | dsh 版本升级后 slot 名或 owner 契约变化 | 填洞失败 | 依赖 `dsh.client`/SlotMap 类型检查；升级时随对应 dsh 版本验证 |
