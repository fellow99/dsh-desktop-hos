## 0. 结论先行

附件3 需要技术侧回答的共 **11 个检查项**（表第 15–18 行）。对照本工程现状：

| # | 检查项 | 现状结论 | 工作性质 |
|---|---|---|---|
| 1 | 关键字过滤措施 | ❌ **不具备**，需新增 | App 技术（内置插件） |
| 2 | 日志留存（时间/项目） | ⚠️ 仅本地会话与开发日志，**不满足**服务者集中留存要求 | App 技术 + **云侧后端** + 制度 |
| 3 | 安全检测和技术措施 | ✅ 部分具备（围栏 / token 认证 / 拦截 / TLS / 最小权限），需补漏扫与少量加固 | 技术（大部分已在）+ 检测报告 |
| 4 | 用户注册信息留存 | ❌ 无注册体系（表填注册用户 0）——**需先做第 5 项实名门**，否则勾"否" | **决策点**：上轻量账号 or 书面说明 |
| 5 | 实名制 | ❌ 无账号、无身份核验 | App 技术（华为账号一键登录）+ 云侧 |
| 6 | 保存公民个人信息 | ⚠️ 设备本地存有 API Key / 对话内容 / 匿名 ID；**无隐私政策页（0.1.5 F1 遗留未闭环）** | App 技术 + 制度 + 云侧 |
| 7 | 违法有害信息处置技术措施 | ❌ 无处置措施（仅依赖模型提供方平台侧审核） | App 技术（与第 1 项同一插件）+ 云侧应急开关 |
| 8 | 应急处置预案 | ❌ 无预案文档、无远程处置手段 | 制度文件 + App/云 kill switch |
| 9 | 应急处置演练 | ❌ 未开展 | 制度执行（演练 + 记录存档） |
| 10 | 投诉举报接收处理制度 | ❌ 应用内无举报入口、无处理制度 | App 入口（ArkWeb 表单）+ **云侧后端** + 制度 |
| 11 | 举报、投诉信息留存 | ❌ 无接收渠道，无留存 | 云侧存储 + 制度 |

**总体判断**：本应用是**本地优先（local-first）架构**——dsh Host 进程内运行于用户设备、用户自带模型 API Key（BYOK）、应用本身不运营内容、不做公网信息分发。但按《生成式人工智能服务管理暂行办法》第 2/9/17 条，向境内公众呈现模型生成文本的一方即**服务提供者**，安全评估义务不因其"本地架构"而免除。因此需在三个面补齐：

1. **App 侧**：1 个内容安全插件（关键词过滤 + 审计 + 实名门 + 应急开关执行点）、隐私/协议页、投诉举报入口、API Key 静态加密；
2. **云侧（附件3 已申报"腾讯云·广州·1 台"）**：最小后端——配置/词库下发、审计日志接收（≥180 天）、举报表单与存储、（可选）登录核验；
3. **制度侧（非代码）**：安全管理、内容审核、日志留存、应急预案、投诉处理、演练等 6–8 份制度文件与记录模板。

> ⚠️ 一致性前提：附件3 已填写"境内服务器：广州 / 数量 1 / 云平台：腾讯云 / 无境外服务器 / 无境外用户"。云侧后端必须**真实部署在境内腾讯云、域名完成 ICP 备案与公安联网备案**，且全部数据不出境——表、系统、自评估报告三方口径必须一致。

## 2. 逐项评估与实现方案

> 每项结构：依据 → 现状差距 → 怎么实现 → 建议填报。

### 2.1 是否具有关键字过滤措施 —— ❌→【是】

**依据**：《生成式人工智能服务管理暂行办法》第 4、14 条；大模型登记材料明确要求提交"拦截关键词库"；检查要求公安提醒第 2 条（过滤覆盖面要足）。

**现状**：无任何内容关键词过滤。模型提供方（如 DeepSeek）平台侧有输入/输出审核，但服务提供者不能以此完全替代自身措施（审核口径与取证均不在本应用侧）。

**实现（新增内置插件 `plugins/harmony-plugin-content-safety`）**：

- 利用 dsh 已有的 **`llm/stream` 瀑布钩子**（"围绕每次模型流式调用的 waterfall，可检查入参、包装输出流、yield 自有分片短路"，见 dsh 源码 `packages/llm/llm/src/index.ts:75` 与现成用例 `packages/core/agent-loop/src/invariant.ts:21`）：
  - **输入侧**：扫描 `options.messages`（含系统提示、用户文本、工具结果），命中即**不调用模型**，短路返回标准拒答并记录拦截事件；
  - **输出侧**：包装 `next()` 返回的 `AsyncIterable<StreamChunk>`，按窗口累积文本扫描，命中即中断流并替换为标准提示（如"输出包含违规内容，已停止生成"）。
- **词库**：随包内置基础词库 `keywords/base.json`（分级：`block` 阻断 / `review` 放行+记事件）；启动时及每 6 小时从腾讯云 `GET /api/v1/config` 拉增量词库（版本号 + 签名校验，防篡改）；词库仅在内存与沙箱内更新，**不上传用户文本**（词库匹配全部在端侧完成）。
- 头像/昵称等 UGC 过滤（公安提醒第 2 条）：**本应用无头像/昵称/公开发布功能，不适用**，在自评估报告中书面说明。
- 挂载方式：插件按本工程约定放 `plugins/harmony-plugin-*`（`collect-dsh.mjs` 自动物化进 `dsh-dist/node_modules`），并加入 `profiles/desktop/package.json` 的 `dsh.profile.bundles`（与 `harmony-plugin-market-runtime` 同路径，纯服务插件无需 preset 工具行）。

代码骨架（ESM，风格对齐现有 `plugins/harmony-plugin-exec/lib/index.js`）：

```js
import z from '@deepseek-ai/schemastery'
export const name = 'harmony-plugin-content-safety'
export const inject = ['llm']
export const Config = z.object({
  endpoint: z.string().default('https://<合规域名>/api/v1'),
  blockAction: z.union(['refuse', 'mask']).default('refuse'),
})
export function apply(ctx, config) {
  const kw = loadKeywordStore()              // 内置 base.json + 云端增量（带签名/版本）
  const audit = makeAuditSink(config.endpoint) // 本地 JSONL + 批量上报
  ctx.on('llm/stream', (options, next) => {
    if (!kw.serviceEnabled) return refuse('服务暂不可用，请稍后再试')      // 应急开关
    if (!identity.verified()) return refuse('请先完成实名验证后再使用')    // 实名门（见 2.5）
    const hit = scanMessages(options.messages, kw)                        // 输入扫描
    if (hit) { audit.record('input.blocked', hit); return refuse(REFUSAL_TEXT) }
    return filterOutputStream(next(), kw, hit => audit.record('output.blocked', hit))
  }, { global: true, prepend: true })
}
```

**验收/取证**：构造违禁用例→输入被拦截且不产生模型调用（抓包证实）；输出诱导用例→生成被中断；词库云端更新→端侧版本号变化生效；全程录屏截图供现场检查。

**填报**：勾「是」。

### 2.2 是否落实日志留存（留存时间 / 日志留存项目）—— ❌→【是，180 天】

**依据**：《网络安全法》第 21 条（网络日志留存**不少于六个月**）；检查要求公安提醒第 3 条（登录日志至少 **180 日**）、第 4 条（日志需含 **IP 及端口**）。

**现状**：

- 设备本地有会话 SQLite/JSONL（属用户内容，非安全审计日志）与 console/hilog（不持久、不上报）；
- **服务者侧无任何日志**：无后端、无登录日志、无 IP/端口记录。当前架构下公安要求"提供日志"时无法提供。

**实现（端侧采集 + 云端留存）**：

1. **端侧审计事件**（由 2.1 插件统一写 `userData/.dsh/audit/audit-YYYYMMDD.jsonl`）：

   | 事件类型 | 字段（最小化，不留对话全文） |
  |---|---|
   | `app.startup` / `app.shutdown` | 时间、appVersion、匿名安装 ID（复用 dsh `.anonymous-user-id`）、OS 版本 |
   | `auth.login` / `auth.logout` / `auth.verify-failed` | 时间、账号 openID（哈希）、结果（**IP/端口在云侧补记**） |
   | `model.call` | 时间、匿名 ID、provider、model、会话 ID、字符数（**不含正文**）、耗时、结果 |
   | `input.blocked` / `output.blocked` | 时间、规则 ID、级别、命中词归类（不记原词原句）、处置动作 |
   | `config.updated` / `config.killswitch` | 词库/开关版本、生效时间 |
   | `report.submitted` | 举报单 ID、类型 |

2. **上报**：批量 HTTPS `POST /api/v1/events`（压缩、失败指数退避、本地缓存最多 7 天）；云侧自动记录**来源 IP、源端口、时间、UA、TLS 版本**（公安提醒第 4 条在云侧天然满足）。
3. **云侧留存**：热存 180 天 + 冷归档，到期自动删除；接入访问控制与备份。**统一按 180 天（≥6 个月）填报**，一处口径避免打架。
4. 本地 webserver 访问记录：dsh Host 对本地 webserver 请求增加访问日志（方法/路径/时间/远端地址），落沙箱日志文件，随审计事件抽样上报。
5. 制度：配套《日志留存与备份管理制度》（留存范围、期限、查阅审批、保密、销毁）。

**填报**：勾「是（留存时间：**180** 天）」；"日志留存项目"填：
> 用户登录认证日志、信息生成服务调用日志（时间、模型提供方、匿名标识、处置结果）、关键词拦截日志、投诉举报受理处置日志、系统运行日志、网络访问日志（含来源 IP 及端口）；在境内腾讯云集中存储，留存不少于 180 天。

### 2.3 是否落实安全检测和技术措施 —— ✅【是】（需补两项取证/加固）

**现状（已具备，可直接写入自评估报告）**：

1. dsh webserver 浏览器会话 **token + 签名 cookie** 认证，裸访问 401（`src-main/main.js:586-600`）；
2. **特权方法 loopback 围栏**：凭据/配置类 RPC 非 loopback 一律 403，局域网其他设备不可达（`PRIVILEGED_METHODS`，`src-main/main.js:710-754`）；
3. 内嵌 Chromium **禁止弹窗、禁止外部导航**，外部网页统一 ArkWeb（`ExternalWeb.ets`），已移除 `browsable`/`viewData` 语义；
4. 模型 API 等外联均走 **HTTPS**，Node 默认 TLS 证书校验（**严禁**代码中出现 `rejectUnauthorized:false`，提包前全仓扫描）；
5. 命令执行工具有**命令黑名单 + 路径围栏 + 用户审批**（`harmony-plugin-exec`，`ui-approval`）；文件写操作受 workspace 白名单与提权审批约束（`DSH_EXTRA_WRITABLE_ROOTS`）；
6. 插件安装 `ignoreScripts: true`（不执行安装脚本）、市场操作用户显式确认；
7. 系统权限最小化（仅 4+1 项网络/保活权限 + 按需目录 ACL）；
8. AI 生成内容显式标识；release 包发布证书 + Profile 签名断言。

**需补强**：

- **依赖漏洞扫描**：CI 增加 `pnpm audit`/`npm audit`（dsh-dist 依赖树）+ 鸿蒙侧二进制物料检查；上线前出具一份**漏洞扫描报告**（检查要求明确：有高危漏洞须填附件4整改，无高危则附件4免填；自测或第三方均可）。
- **局域网暴露面加固**：webserver 因鸿蒙 loopback 隔离绑 `0.0.0.0`，虽有 token cookie + 特权围栏，建议在主进程对裸 HTTP server 加**同机连接白名单**（`server.on('connection', sock => 非本机局域网IP/非loopback 即 destroy)`），纵深防御局域网伪造请求。
- 配置/词库下发接口做**响应签名校验**（防中间人投毒词库/伪造关停指令）；举报/上报接口做基础频控。
- 隐私合规自测（机器+人工审核、截图存证），出具《隐私合规检测报告》（检查要求的独立交付物，可与本批复用隐私梳理成果）。

**填报**：勾「是」，自评估报告中按上述清单展开。

### 2.4 是否留存用户注册信息 —— ❌→ 取决于实名门决策

**依据**：与 2.5 实名制一体两面；留存时间同样适用 ≥180 天口径。

**现状**：无注册体系，附件3 填注册用户 0。两条可选路径：

| 路径 | 做法 | 本表填报 | 风险 |
|---|---|---|---|
| A（推荐）建轻量实名门 | 见 2.5，云端留存账号标识与登录日志 | 「是（180 天）」 | 需开发 + 云接口；但完全满足检查要求与公安提醒第 1 条，且堵住现场检查最大追问 |
| B 维持无账号 | 不收集注册信息；书面说明"实名由模型提供方在 API Key 侧完成（Key 持有人在模型平台已实名），应用不区分用户" | 「否」 | 服务提供者义务履行依赖审核口径；公安提醒明确要求"对无实名用户限制使用"，现场检查大概率被要求整改 |

### 2.5 是否落实实名制 —— ❌→【是】

**依据（2026-10-11 已逐条核对官方原文）**：
- 《网络安全法》第 24 条：网络运营者为用户提供**信息发布、即时通讯**等服务，应当要求用户提供真实身份信息；不提供的不得提供相关服务。
- 《移动互联网应用程序信息服务管理规定》（2022 修订）**第 6 条**：App 提供者为用户提供信息发布、即时通讯等服务的，应基于**移动电话号码、身份证件号码或统一社会信用代码**进行真实身份信息认证，不提供不得提供相关服务。
- 《互联网信息服务深度合成管理规定》**第 9 条**：深度合成服务提供者应基于**移动电话号码、身份证件号码、统一社会信用代码或国家网络身份认证公共服务**对使用者进行真实身份信息认证，**不得向未认证使用者提供信息发布服务**；第 19 条要求舆论属性/社会动员能力的深度合成服务履行备案。
- 《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》（2018）**第 5 条第（二）项**：安全评估重点内容明列"**用户真实身份核验以及注册信息留存措施**"——这就是附件3「是否落实实名制」的直接法源；同条第（三）项要求留存操作时间、类型、**网络源地址和目标地址、网络源端口**等日志（对应附件3 日志项目与公安提醒第 4 条）。
- 注意：《生成式人工智能服务管理暂行办法》（2023）**全文并无"真实身份"字样**（此前常见的"暂行办法第 9 条要求实名"系二手误引，第 9 条实为内容生产者责任与服务协议）；实名义务是经上述 App 规定/深度合成规定/网络安全法传导的。暂行办法相关条款为第 9 条（内容生产者责任）、第 14 条（违法内容处置）、第 15 条（投诉举报）、第 17 条（安全评估+算法备案）。
- 检查要求公安提醒第 1 条（第三方账号注册须加手机验证门槛，未实名限制浏览及使用权限）——海珠属地执行口径比法条字面更严。

> 附件3 当前 H14「实名认证方式」填的是"个人主体"——这是**开发者主体类型，不是用户实名方式**，口径错误，需改为实际方式（见 §6）。

**实现路径（关键前置：华为账号一键登录仅限企业开发者，2026-10-11 已查官方文档确认）**：

> 华为官方《申请账号权限》明确：**"华为账号一键登录、获取您的手机号、获取收货地址权限，仅支持企业开发者申请，不支持个人开发者申请。个人开发者可使用华为账号登录或静默登录实现登录。"** 一键登录权限申请入口对个人开发者**不可见**；自检条件还包括：必须是 HarmonyOS NEXT 应用（本工程是 ✅）、非游戏/银行类（✅ 工具类）、应用须上架应用市场或说明原因（✅ 计划上架）、近 3 个工作日内审、通过后最迟 25 小时生效。设备支持 Phone/Tablet/**PC·2in1**（与本工程目标设备一致）。

| 路径 | 适用主体 | 能拿到什么 | 对公安"手机验证门槛" | 结论 |
|---|---|---|---|---|
| **A. 华为账号一键登录**（`quickLoginAnonymousPhone` scope） | **仅企业开发者**（含个体工商户：凭营业执照注册/升级为企业开发者） | UnionID/OpenID + **华为账号绑定的手机号**（服务端 code 换完整手机号） | ✅ 满足 | **推荐**，但需先把 AGC 主体升级为企业/个体工商户，与 `上线整改-0.2.0.md` 路线 2 合并决策 |
| B. 华为账号登录 / 静默登录（基础能力） | 个人开发者可用，无需权限审批 | 仅 UnionID/OpenID（**拿不到手机号**） | ❌ 第三方账号但无手机号验证，公安提醒第 1 条明确要求"增加手机验证门槛"，现场检查难过 | 只能作为登录体验，**不能单独作为实名制答案** |
| C. 自建手机号短信验证 | 理论上个人可做 | 手机号 | ✅ 满足 | 腾讯云等国内短信签名申请通常要求企业资质（签名需与备案主体/上架应用一致），个人主体实践中同样受限；列为备选，需先向云厂商确认 |
| D. 运营商一键取号 SDK（移动/联通/电信认证） | 企业资质 | 手机号 | ✅ 满足 | 同样要求企业资质，备选 |

**结论：实名制这一格实际上倒逼主体升级**——个人开发者拿不到任何一条合规的"手机号验证"通道。建议与算法备案主体（0.2.0 文档路线 2：注册个体工商户）一并办理，AGC 开发者账号同步升级为企业开发者，然后走路径 A。

路径 A 的实现：

1. AGC「开放能力管理」申请"华为账号一键登录"权限（申请原因：本应用为生成式 AI/深度合成服务，依据《互联网信息服务深度合成管理规定》第 9 条、《移动互联网应用程序信息服务管理规定》第 6 条须对使用者进行真实身份信息认证，属法规要求的必要业务场景；附应用介绍与上架计划）；配置签名指纹与 Client ID。
2. 客户端：运行时中 `Login.ets` / `QuickLoginButtonComponent.ets` 演示件已存在（已申请 `quickLoginAnonymousPhone` scope）但**当前未接线**（0.1.5 已查证），改造为正式登录流程；注意 release 混淆白名单需保留 `quickLoginAnonymousPhone` 属性；预取号 5 秒超时、未登录/境外账号回退其他方式。
3. 服务端（必备）：客户端把 Authorization Code 送腾讯云后端，由后端调华为 `oauth2/v6/quickLogin/getPhoneNumber` 换取**完整手机号 + UnionID/OpenID**，换发本应用会话凭证；云端存 openID 哈希、掩码手机号、注册/最近登录时间。App Secret 只存服务端。
4. **未实名限制（公安提醒原话）**：未完成登录前，应用仅可浏览空壳界面，**不能新建会话/发起模型调用**——门控点即 2.1 插件 `llm/stream` 最前置（无会话凭证直接短路），不依赖 UI 自觉。
5. **账号注销（强制，检查要求第 5 条特别点名"永久注销"）**：
   - 应用内入口（设置/关于页）→ 云 `DELETE /api/v1/account`（云端硬删或立即匿名化，出具删除回执）；
   - 本地提供"清除全部数据"（删除 `userData/.dsh`：凭据、会话、审计缓存）；
   - 注销后不得再用历史数据，合规审计日志中仅保留不可复原的操作记录。
6. 协议合规：一键登录页必须展示并由用户勾选同意《华为账号用户认证协议》（官方指定链接）+ 本应用用户协议/隐私政策；手机号二次放号风险按官方建议做额外校验设计。

**填报**：勾「是」；"实名认证方式"路径 A 填「**手机号验证（华为账号一键登录）**」；若最终走短信通道则填「手机号短信验证」。路径 B（仅 UnionID）不足以支撑本格填"是"。

## 3. 腾讯云最小合规后端设计（对应已申报的"广州·1 台"）

| 接口 | 方法 | 作用 | 留存/安全 |
|---|---|---|---|
| `/api/v1/config` | GET | 应急开关、公告、词库版本与增量包 | 响应签名；公开只读；词库不含用户数据 |
| `/api/v1/events` | POST | 审计日志批量上报 | 服务端补记 IP/端口/UA；鉴权 + 频控；180 天 |

## 7. 风险与决策点（需业务/合规确认）

1. **主体升级是实名门的硬前置（2026-10-11 已查官方文档确认）**：华为账号**一键登录（取手机号）仅限企业开发者**，个人开发者只能拿 UnionID/OpenID，过不了公安"第三方账号须加手机验证门槛"这一条；自建短信/运营商取号也普遍要求企业资质。因此实名制与 `上线整改-0.2.0.md` 路线 2（个体工商户）强绑定：要么升级主体走路径 A（推荐），要么不做账号体系、接受现场检查责令整改风险。建议先电话咨询海珠网安（张警官）与 AGC 客服确认个体户升级口径。
2. **主体资格联动**：承 `上线整改-0.2.0.md`，算法备案/大模型登记主体（个人 vs 个体工商户）会影响云服务、华为账号服务、短信签名的开通主体，需与该文档路线选择一并决策。
3. **"端侧关键词过滤"的定性**：0.2.0 文档记录了"前端内容过滤是否构成实质性修改、导致大模型登记升级为备案"的边界问题。本方案过滤为**拦截/阻断**（不重组、不优化模型输出），但仍建议与属地网信办确认口径。
4. **webserver 绑 0.0.0.0 的局域网暴露面**：token+围栏之外，建议 P1 补同机连接白名单，现场检查可能问及"同网设备能否调用"。
5. **插件供应链**：市场插件具备文件/命令能力且来源为 GitHub/npm，虽非备案直接检查项，但属"技术措施"问询面；保持用户确认安装、`ignoreScripts`、来源展示，必要时限制市场可用清单。
6. **成本**：云服务器/备案/证书（可免费证书）/华为账号服务均低成本；主要成本在开发（插件 + 实名门）与制度办理周期，建议安全评估材料与 P0 技术项并行启动。
