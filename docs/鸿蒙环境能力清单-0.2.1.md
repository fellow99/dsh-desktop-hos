# 鸿蒙环境能力清单 · 0.2.1（Electron on HarmonyOS / dsh-desktop-hos）

> **适用版本**：`dsh-desktop-hos` 0.2.1（`versionName` 0.2.1 / `versionCode` 1009，dsh `dsh-v0.2.1-rc.2`）
> **更新日期**：2026-10-21
> **定位**：本文件是本版**能力现状的唯一权威结论**。能力集合以本工程（Electron 路线）为基准，同一张表里并列给出 **HarmonyOS Edition（`dsh-desktop-ark`，ArkWeb + 进程内 Node）** 的对标状态，用于回答"两个鸿蒙版本各能做什么、为什么不同"。
> **本文只记结论**：逐项实测过程、原始日志与复现步骤不保留在本文（历史分析见 [`鸿蒙环境能力清单-v0.1.5.md`](./鸿蒙环境能力清单-v0.1.5.md) 与本工程 `docs/` 其余文件）。
> **图例**：✅ 可用（有真机或等价实证）｜⚠️ 受限 / 部分可用 / 有前置条件｜❌ 无此能力或已决策不做｜❓ 未取证。

## A. 两个版本的环境标识

| 项 | Electron on HarmonyOS（本工程） | HarmonyOS Edition（`dsh-desktop-ark`） |
|---|---|---|
| 界面渲染 | Electron 37 内置 Chromium | 系统 ArkWeb（不随包带浏览器内核） |
| Node 运行时 | Electron 内置 Node 22.17 | 进程内 `libnode.so` v24.2.0（`node::Start`） |
| 平台适配方式 | 13 个上游源码补丁 + profile + 插件 | 上游零补丁：`ohos` profile + `@dsh-ohos/bundle` + 带标记垫片 |
| 设备形态 | 2in1 / tablet | 2in1 / tablet |
| 目标设备 | HarmonyOS 6.1.0.135（API 24） | HarmonyOS 6.1.0.135（API 24） |
| 沙箱策略 | `workspace-write` + 审批 `ask` | `workspace-write`（`sandbox: none`，围栏在 fs 层） |
| 运行时形态 | JIT（需受限权限 `ALLOW_WRITABLE_CODE_MEMORY`） | 默认 `compat`（`--jitless`，零 ACL）；`jit` 变体需 1 项 ACL |

> **版本状态提示**：0.2.1 本次只完成**构建与签名**验证；下表的 ✅ 证据来自 0.2.0 / 0.1.5 真机复验（补丁集与 0.2.0 逐条一致），0.2.1 的真机回归（R6）待做。

## C. 一句话结论

- **两份能力的差距不在"鸿蒙能不能"，而在"用哪条路走"**：Electron 路线复用了完整的 Node/Chromium 语义，代价是 JIT 受限权限与更大的包体；ArkWeb 路线零补丁、零 ACL，代价是平台适配必须落在 seam 插件与垫片上。
- **hos 独有**：命令执行（常驻 sh）、纯 JS 搜索、删除/移动/复制/chmod、托盘、窗口状态记忆、插件市场、任意 ArkTS 能力桥。
- **ark 独有**：零 ACL 可安装（`compat`）、撤销桌面权限后的三根目录授权闭环、零上游补丁。
- **两侧共同的天花板**：无 PTY、无进程沙箱、无开机自启、无静默更新、无服务端缩略图、2in1 无真正后台。
